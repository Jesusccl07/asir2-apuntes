Virtualización y VirtualBox

Conceptos 1–8 del temario.

VirtualBox c.1

Hipervisor de tipo 2 de Oracle. Base libre con licencia GPLv3. Usamos la versión 7.1.18. Hay binarios para Windows, macOS, Linux y Solaris, además del código fuente y las «older builds».

Extension Pack c.2

Complemento propietario (PUEL, gratis para uso personal/educativo). Añade USB 2.0/3.0, VirtualBox RDP (VRDE), cifrado de discos, arranque PXE de Intel y webcam. Su versión debe coincidir con la de VirtualBox.

Guest Additions c.3 · c.16

Controladores que se instalan dentro del invitado: ajuste automático de resolución, portapapeles y arrastrar/soltar bidireccional, carpetas compartidas, ratón integrado, sincronización de hora. Deben coincidir con la versión de VirtualBox y con el núcleo exacto.

Configuración de la MV c.4

RAM, vídeo (128 MB), procesadores, disco dinámico (crece según uso) en controladora SATA, unidad óptica, portapapeles y arrastrar/soltar. Revisar que VirtualBox no muestre advertencias.

Instantáneas c.5

Guardan el estado de disco (y opcionalmente memoria) en un momento dado para volver atrás. Se crean preferentemente con la MV apagada. Nombres de práctica: i01_limpia, i02_ssh_basico, i_antes_t1.

NAT vs Red Interna c.6

NAT: el invitado sale a Internet a través del anfitrión (10.0.2.x / 10.0.3.x, DHCP) pero no es accesible desde otras MV. Red interna: red aislada entre MV con el mismo nombre (intnet2), sin Internet ni anfitrión.

ISO vs OVA c.7

ISO: imagen de un disco de instalación; hay que instalar el SO. OVA: paquete OVF (descriptor + discos) con una MV ya instalada y configurada que se importa.

SHA-256 y MD5 c.8

Funciones hash para comprobar la integridad de una descarga: el hash calculado debe coincidir con el publicado. MD5 está roto frente a colisiones; SHA-256 es el recomendado.

Conceptos de acceso remoto

Conceptos 22–24.

Acceso remoto vs asistencia remota

Acceso remoto: el administrador entra a un equipo (a menudo desatendido) para administrarlo. Asistencia remota: se ayuda a un usuario que está delante y comparte su sesión, normalmente aceptando la conexión.

Servidor vs cliente

El servidor escucha conexiones en un puerto (sshd, TermService, x11vnc). El cliente inicia la conexión (ssh, mstsc, Remmina, TightVNC Viewer).

SSH

Conceptos 25–35 · ejercicios 9, 10 y 11.

SSH (Secure Shell) es un protocolo para administrar equipos remotos por un canal cifrado: consola, transferencia de ficheros (scp/sftp) y túneles. OpenSSH es la implementación libre más usada, del proyecto OpenBSD, con licencia BSD. OpenSSH Client (ssh, scp, sftp) inicia conexiones; OpenSSH Server (sshd) las atiende. El puerto por defecto es el 22/TCP, y se puede usar cualquier otro (1212, 2222, 3232…).

c.31–33Seguridad, claves y huellas

Algoritmos

Intercambio de claves: curve25519, ECDH, Diffie-Hellman. Firma/host: ed25519, ECDSA, RSA. Cifrado simétrico: AES-GCM, ChaCha20-Poly1305. Integridad (MAC): HMAC-SHA2.

Autenticación

El servidor se autentica con su clave de host, que el cliente compara con ~/.ssh/known_hosts. El usuario se autentica con contraseña, clave pública (authorized_keys), keyboard-interactive o Kerberos.

Aviso de primera conexión

El cliente aún no conoce la huella del servidor. Al aceptarla se guarda en known_hosts. Si después cambia, aparece REMOTE HOST IDENTIFICATION HAS CHANGED: puede ser un ataque man-in-the-middle.

Endurecimiento

AllowUsers (lista blanca), DenyUsers, AllowGroups, PermitRootLogin no, PasswordAuthentication no, MaxAuthTries, MaxStartups.

bash · ejercicios 10 y 11
# restringir acceso
echo "AllowUsers profesorus40" | sudo tee -a /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
# huella del servidor
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
# regenerar claves de host
sudo mkdir -p /etc/ssh/keys.back && sudo cp /etc/ssh/ssh_host_* /etc/ssh/keys.back/
sudo rm /etc/ssh/ssh_host_* && sudo ssh-keygen -A && sudo systemctl restart ssh
# en el cliente tras el aviso
ssh-keygen -R "[10.14.40.199]:1212"
# autenticación por clave
ssh-keygen -t ed25519
ssh-copy-id -p 1212 profesorus40@10.14.40.199
cat ~/.ssh/authorized_keys        # en el servidor

c.34–35X11 Forwarding y túneles

X11 Forwarding: la aplicación gráfica se ejecuta en el servidor y sus ventanas se dibujan en el servidor X del cliente (Xorg en Linux, Xming o VcXsrv en Windows). $DISPLAY pasa a valer localhost:10.0.

Túnel SSH: usa la conexión cifrada como tubería para otro tráfico. Con -L (local), lo que llega a un puerto del cliente se entrega a un puerto del servidor.

bash · ejercicio 11
# servidor: X11Forwarding yes en sshd_config + x11-apps
sudo grep -i "^X11Forwarding" /etc/ssh/sshd_config
ssh -X -p 1212 profesorus40@10.14.40.199
echo $DISPLAY ; xclock &
ps aux | grep xclock               # el proceso corre en el servidor

# túnel: web solo en localhost del servidor
python3 -m http.server 8080 --bind 127.0.0.1     # servidor
ssh -L 8080:localhost:8080 -p 1212 profesorus40@10.14.40.199   # cliente
# navegador del cliente → http://localhost:8080

Escritorio remoto (RDP)

Conceptos 42–50 · ejercicio 12.

RDP

Protocolo de Microsoft para el escritorio gráfico completo (pantalla, teclado, ratón, audio, portapapeles, impresoras). Usa el puerto 3389 TCP (y UDP). Lo atiende el servicio TermService.

RDP vs SSH

RDP da un escritorio gráfico, orientado a Windows. SSH da sobre todo consola de texto, túneles y transferencia de ficheros, y es el estándar en Linux. RDP consume más ancho de banda.

Clientes

Windows: mstsc.exe. Linux: Remmina (con remmina-plugin-rdp), xfreerdp, rdesktop. xRDP es un servidor RDP para Linux.

NLA

Network Level Authentication: autentica al usuario con CredSSP antes de crear la sesión. Ahorra recursos y reduce ataques DoS y vulnerabilidades previas al login.

Windows 10 vs RDS

Windows 10 Pro admite una sesión interactiva: si entra otro usuario, la sesión local se desconecta. Remote Desktop Services de Windows Server (RD Session Host) admite muchos usuarios a la vez, con licencias RDS CAL.

Sesiones vs VDI

Virtualización de sesiones: muchos usuarios comparten un mismo Windows Server. VDI: cada usuario tiene su propia MV de escritorio.

PowerShell · Windows 10
Get-Service TermService | Format-Table Name,Status,StartType
Get-NetTCPConnection -LocalPort 3389 -State Listen
netstat -ano | findstr :3389
tasklist /svc /fi "PID eq 1016"       # svchost → TermService
query user                             # sesiones activas (rdp-tcp#N)
net localgroup "Usuarios de escritorio remoto"
Si un usuario sin permiso (alumnow) intenta entrar, Windows deniega el inicio de sesión remoto aunque la contraseña sea correcta. Solo pueden entrar Administradores y «Usuarios de escritorio remoto».

VNC

Conceptos 51–57 · ejercicio 13.

VNC (Virtual Network Computing) es una tecnología: hay servidores y visores de muchos fabricantes. El protocolo que tienen en común es RFB (Remote Framebuffer, RFC 6143), que transmite los píxeles del framebuffer y reenvía teclado y ratón. Usa el puerto 5900 + n para la pantalla :n.

x11vnc vs TigerVNC

x11vnc comparte la sesión gráfica ya abierta (:0): quien está delante ve lo mismo. TigerVNC (vncserver) crea una sesión gráfica virtual e independiente (:1, puerto 5901).

Herramientas

TightVNC (servidor y visor, GPL), RealVNC (propietario), UltraVNC (Windows, GPL), Vino (servidor GNOME), x11vnc (servidor X11, GPL), Remmina (cliente).

bash · Linux Mint (servidor)
sudo apt install -y x11vnc
mkdir -p ~/.vnc
x11vnc -storepasswd                     # guarda ~/.vnc/passwd
x11vnc -display :0 -rfbauth ~/.vnc/passwd -forever -shared
ss -tlnp | grep 5900 ; ps aux | grep x11vnc
# Ctrl+C para pararlo
-shared hace falta para que dos clientes (TightVNC en Windows y Remmina en Xubuntu) se conecten a la vez. Sin esa opción x11vnc rechaza al segundo con «Not shared & existing client».
Proteger VNC con un túnel SSH
x11vnc -display :0 -rfbauth ~/.vnc/passwd -localhost -forever    # servidor
ssh -L 5900:localhost:5900 profesoru40@10.14.40.104               # cliente
# el visor se conecta a localhost:5900 y todo viaja cifrado por SSH

E09SSH básico · Ubuntu 1212 · Windows Server 3232 · PuTTY▶

E11X11, claves de usuario y túnel SSH▶
