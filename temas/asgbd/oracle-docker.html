Entrar en Oracle

Docker Desktop › Containers
  • Abre Docker Desktop › Containers. Oracle-ASIR2 debe tener el punto verde. Si no, pulsa ▶ Start y espera 1 minuto.
  • Pincha en el nombre Oracle-ASIR2 › pestaña Exec. Sale una terminal sh-4.4$.
 sh-4.4$
sqlplus / as sysdba
Connected to:
Oracle AI Database 26ai Free Release 23.26.3.0.0 - Develop, Learn, and Run for Free
SQL>

Ya estás dentro como SYS (el administrador). Cada orden termina en ; y se ejecuta con Intro. Para salir: exit

OJO

En sqlplus la flecha ↑ no recupera la orden anterior (salen caracteres raros). Vuelve a escribirla o pégala (clic derecho › pegar / Ctrl+Shift+V). Si una orden se queda a medias con un número delante (2, 3…), escribe ; o / y Intro.

Crear la PDB

Raíz · CDB$ROOT
Ver las PDB que hay
 SQL>
SELECT NAME, OPEN_MODE FROM V$PDBS;
NAME          OPEN_MODE
------------- ----------
PDB$SEED      READ ONLY
FREEPDB1      READ WRITE
Dónde están los ficheros de la plantilla (PDB$SEED es siempre con_id = 2)
 SQL>
SELECT name FROM v$datafile WHERE con_id = 2;
/opt/oracle/oradata/FREE/pdbseed/system01.dbf
/opt/oracle/oradata/FREE/pdbseed/sysaux01.dbf
/opt/oracle/oradata/FREE/pdbseed/undotbs01.dbf
Crear la PDB copiando la plantilla (todo en una línea)
 SQL>
CREATE PLUGGABLE DATABASE pruebajcs ADMIN USER pdbadmin IDENTIFIED BY oracle FILE_NAME_CONVERT=('/opt/oracle/oradata/FREE/pdbseed/','/opt/oracle/oradata/FREE/PRUEBAJCS/');
Pluggable database created.
CLAVE

FILE_NAME_CONVERT = (de dónde copio, a dónde copio). La carpeta destino es el nombre de la PDB en MAYÚSCULAS, terminado en /.

Abrir y guardar el estado (recién creada queda MOUNTED, cerrada)
 SQL>
ALTER PLUGGABLE DATABASE pruebajcs OPEN;
ALTER PLUGGABLE DATABASE pruebajcs SAVE STATE;
SELECT NAME, OPEN_MODE FROM V$PDBS;
Pluggable database altered.
Pluggable database altered.
PRUEBAJCS     READ WRITE

Crear los tablespaces

Dentro de PRUEBAJCS
BIGFILE"Un solo fichero sin posibilidad de añadir ficheros"Se amplía o reduce con RESIZE del tablespace.

EXTRA

Si te pidieran quitar USERS y existiera: DROP TABLESPACE users INCLUDING CONTENTS AND DATAFILES;

OJO

Si no pones BIGFILE ni SMALLFILE

Oracle 26ai crea el tablespace como BIGFILE por defecto: un solo datafile (puede llegar a 32 TB con bloques de 8K). Entonces no podrás añadirle ficheros (ORA-32771).

1. Lo creas sin decir el tipo
 SQL>
CREATE TABLESPACE datos DATAFILE '/opt/oracle/oradata/FREE/PRUEBAJCS/datos01.dbf' SIZE 10M;
2. Compruebas si es BIGFILE (nombre en MAYÚSCULAS)
 SQL>
SELECT tablespace_name, bigfile FROM dba_tablespaces WHERE tablespace_name = 'DATOS';
TABLESPACE_NAME  BIG
DATOS            YES   ← es BIGFILE
3. Si necesitas SMALLFILE: bórralo con sus ficheros y créalo otra vez
 SQL>
DROP TABLESPACE datos INCLUDING CONTENTS AND DATAFILES;
CREATE SMALLFILE TABLESPACE datos DATAFILE '/opt/oracle/oradata/FREE/PRUEBAJCS/datos01.dbf' SIZE 10M;
OJO

Con un DROP TABLESPACE datos; a secas el fichero se queda en disco, y al recrearlo con el mismo nombre sale ORA-01119. Usa INCLUDING CONTENTS AND DATAFILES o pon otro nombre de fichero.

TEST

En el test, DROP USER users; aparece como opción incorrecta para quitar el tablespace USERS. La buena es DROP TABLESPACE: USERS aquí es un tablespace, no un usuario.

05

Crear los usuarios y darles permisos

Dentro de PRUEBAJCS
ENUNCIADO"Podrá escribir en X e Y"QUOTA UNLIMITED ON X QUOTA UNLIMITED ON Y
PERMISOS MÍNIMOScreate session + create tableUno para conectarse, otro para crear tablas.
Usuario replicalientejcs
 SQL>
CREATE USER replicalientejcs IDENTIFIED BY oracle DEFAULT TABLESPACE replicajcs_cliente QUOTA UNLIMITED ON replicajcs_cliente QUOTA UNLIMITED ON replicajcs_cliente2 TEMPORARY TABLESPACE TEMP;
grant create session to replicalientejcs;
grant create table to replicalientejcs;
Usuario mispruebasjcs
 SQL>
CREATE USER mispruebasjcs IDENTIFIED BY oracle DEFAULT TABLESPACE datosjcs_pruebas QUOTA UNLIMITED ON datosjcs_pruebas TEMPORARY TABLESPACE TEMP;
grant create session to mispruebasjcs;
grant create table to mispruebasjcs;
User created.
Grant succeeded.
Grant succeeded.
TIP

Si el usuario ya existía y solo hay que darle permiso en otro tablespace: ALTER USER replicalientejcs QUOTA UNLIMITED ON otro_tablespace;

EXTRA

Borrar un usuario y crearlo otra vez

No viene en los PDF ni en las webs de clase: lo añadí en los apuntes del Word. Es raro que lo pregunten en la teoría, pero te salva en la práctica si creas mal un usuario (nombre equivocado, tablespace por defecto mal…). Si intentas crearlo otra vez sin borrarlo, Oracle da ORA-01920.

Desde la pestaña Exec, como SYS y dentro de la PDB (ALTER SESSION SET CONTAINER = pruebajcs;):

Sin objetos (solo si no tiene ninguna tabla)
 SQL>
DROP USER mispruebasjcs;
Si tiene alguna tabla:
ORA-01922: CASCADE must be specified
to drop 'MISPRUEBASJCS'
Con objetos (el que necesitas si ya creaste la tabla de prueba)
 SQL>
DROP USER mispruebasjcs CASCADE;
User dropped.
Borra el usuario y todas sus tablas.
DROP USERBorra una personaEl usuario (y con CASCADE, sus tablas).
DROP TABLESPACEBorra una habitaciónEl tablespace y, con INCLUDING CONTENTS AND DATAFILES, sus ficheros.
CUIDADO

Si lo haces en la raíz (CDB$ROOT) no encuentra al usuario de la PDB y da ORA-01918: user does not exist. Y no tiene vuelta atrás: tendrás que repetir su CREATE USER y sus grant.

Cambiar el tamaño de los tablespaces

Docker · dentro de la PDB
REGLA

RESIZE pone el tamaño FINAL, no lo que sumas. "Aumenta 20" a uno de 20 → RESIZE 40M.

¿Me quedo sin espacio en un tablespace? Dos opciones
OPCIÓN 1 · REDIMENSIONARAgrandar el datafile que ya tieneVale para BIGFILE y SMALLFILE.ALTER DATABASE DATAFILE '…/datos01.dbf' RESIZE 20M;
OPCIÓN 2 · AÑADIR DATAFILEMeterle otro ficheroSolo SMALLFILE. En un BIGFILE da ORA-32771.ALTER TABLESPACE datos ADD DATAFILE '…/datos02.dbf' SIZE 70M;

Ver tamaños antes
 SQL>
SELECT FILE_NAME, BYTES/1024/1024 MB FROM DBA_DATA_FILES;

09

Borrar, desenchufar y empezar de cero

Desde la raíz · CDB$ROOT
Borrar la PDB del todo (para repetir la práctica)
 SQL>
ALTER SESSION SET CONTAINER = CDB$ROOT;
ALTER PLUGGABLE DATABASE pruebajcs CLOSE;
DROP PLUGGABLE DATABASE pruebajcs INCLUDING DATAFILES;
CUIDADO

Esto borra la PDB y todo lo que tiene. Úsalo solo con PDB de práctica.

PLUG / UNPLUG

Quitar la PDB sin perder sus datos y volver a enchufarla

La PDB se “desenchufa” a un fichero .xml que describe sus datafiles. Con KEEP DATAFILES los ficheros se quedan en disco y con NOCOPY se vuelve a enchufar usándolos tal cual.

1. Cerrar y desenchufar (genera el .xml; sin este paso no existe)
 SQL>
ALTER PLUGGABLE DATABASE pruebajcs CLOSE;
ALTER PLUGGABLE DATABASE pruebajcs UNPLUG INTO '/opt/oracle/oradata/FREE/PRUEBAJCS/pruebajcs.xml';
2. Quitarla dejando los ficheros
 SQL>
DROP PLUGGABLE DATABASE pruebajcs KEEP DATAFILES;
Pluggable database dropped.
3. Enchufarla otra vez, abrirla y guardar el estado
 SQL>
CREATE PLUGGABLE DATABASE pruebajcs USING '/opt/oracle/oradata/FREE/PRUEBAJCS/pruebajcs.xml' NOCOPY;
ALTER PLUGGABLE DATABASE pruebajcs OPEN;
ALTER PLUGGABLE DATABASE pruebajcs SAVE STATE;
Pluggable database created.
Pluggable database altered.
Pluggable database altered.
INCLUDING DATAFILESBorra la PDB y sus ficherosNo se puede recuperar.
KEEP DATAFILESQuita la PDB, deja los ficherosSe vuelve a enchufar con el .xml.
