Arquitectura de Oracle

Un servidor Oracle = instancia (memoria + procesos) + base de datos (ficheros en disco). Oracle es un SGBD relacional.

Instancia

Memoria (SGA + PGA) y procesos. Un servidor puede tener varias instancias.

Base de datos

Los ficheros en disco: datafiles, control files y redo logs.

Listener

Proceso que recibe las conexiones de red de los clientes y las dirige a la instancia que corresponda. Escucha en el puerto 1521.

Procesos cliente

Cualquier programa que el usuario lanza contra la BBDD (SQL Developer, sqlplus…).

Procesos servidor

Procesos del gestor que atienden las peticiones de los clientes. Cada uno tiene su PGA.

Procesos background

Hacen las tareas internas del gestor (pmon, smon, dbw0, lgwr, ckpt…).

Memoria

PGA (Program Global Area)

Memoria privada reservada para cada proceso servidor que atiende a un cliente.

SGA (System Global Area)

Memoria compartida de la instancia. Partes: Shared Pool, buffer de datos y buffer redo log.

Shared Pool

Library cache + dictionary cache. Guarda las sentencias SQL ejecutadas recientemente.

Buffer de datos

Guarda los últimos registros (bloques) consultados.

Buffer redo log

Guarda la información de las modificaciones hechas sobre la BBDD antes de escribirla en los ficheros redo log.

Ficheros

Redo log (rehacer)

Guardan todas las transacciones o modificaciones (INSERT, UPDATE, DELETE). Sirven para recuperar la BBDD si hay problemas. Suele haber varios: REDO01.LOG, REDO02.LOG, REDO03.LOG.

Un registro de redo contiene: identificación de la transacción, dirección de bloque, número de fila, número de columna, valor anterior y valor nuevo.

Ficheros de control (control files)

Información sobre los ficheros de la BBDD; registran los cambios importantes de estructura. CONTROL01.CTL, CONTROL02.CTL, CONTROL03.CTL. Mínimo recomendado: 2 copias en discos diferentes, para restaurar si uno se daña.

Contienen: arranque y parada, nombres de datafiles y redo log, checkpoints, fecha de creación y nombre de la BBDD, estado on-line/off-line de los ficheros.

Ficheros de datos (datafiles, .DBF)

Donde se guardan los datos. Cada uno pertenece a un tablespace.

Otros ficheros

Fichero de parámetros, fichero de password, etc.

Tablespace ↔ datafile

Un tablespace (lógico) se guarda en uno o varios datafiles (físico). Un bloque Oracle está formado por varios bloques del S.O.

Datafile y tablespace

Un datafile pertenece a un solo tablespace. No se puede compartir entre dos.

Tablespace

Espacio donde se ubican las tablas. Sirve para organizar la información (uno para personal, otro para comercial…).

Modelo relacional en Oracle

Esquema

Esquema = usuario. Los objetos de un usuario (tablas, índices, sinónimos, vistas) forman su esquema.

Diccionario de datos

"Información de la información". Se consulta con vistas de cuatro tipos:

  • DBA_ todo, para el DBA
  • ALL_ lo que el usuario puede ver
  • USER_ lo que es del usuario
  • V$ vistas dinámicas de rendimiento y estado

Concurrencia y consistencia

Segmento de rollback (undo)

Guarda la imagen antigua al escribir. Las lecturas de otros usuarios se hacen sobre él, así que ven el dato antiguo hasta el COMMIT.

COMMIT

Confirma la transacción y establece la imagen nueva de los datos.

ROLLBACK

Deshace la transacción y vuelve a la imagen antigua.

Problemas del segmento de rollback

Espacio insuficiente para las transacciones, error de consistencia de lectura y bloqueo de transacciones.

Procesamiento de una sentencia

Se distingue el proceso de una consulta (SELECT) y el de una sentencia DML (INSERT, UPDATE, DELETE).

Instalación en Docker parámetros del docker run

--name

Nombre del contenedor.

-p 1521:1521

Enlaza un puerto del host con uno del contenedor. Es el puerto donde escucha el listener.

-e

Define variables de entorno del contenedor.

ORACLE_PWD

Contraseña de los usuarios SYS y SYSTEM.

ORACLE_CHARACTERSET=AL32UTF8

Juego de caracteres de la BBDD.

ENABLE_ARCHIVELOG=true

Activa el modo archivelog: las transacciones de los redo logs se archivan antes de sobrescribirse.

ENABLE_FORCE_LOGGING=true

Modo de registro forzado (diagnóstico y depuración).

-v oradata:/opt/oracle/oradata

Volumen "oradata" montado en esa ruta para que los datos persistan aunque se borre el contenedor.

Imagen y arranque

La imagen container-registry.oracle.com/database/free:latest se descarga la primera vez. Está lista cuando el log dice DATABASE IS READY TO USE!. Se arranca y para con los botones Start y Stop de Docker Desktop. Para abrir una terminal en el contenedor se usa la pestaña Exec.

CDB y PDB arquitectura multitenant

CDB (Container Database)

Base de datos contenedora. Tiene casi todas las partes de trabajo: control files, datafiles, undo, temporales y redo logs. Aloja el diccionario de datos del contenedor raíz y de los objetos visibles para todas las PDB. Su raíz se llama CDB$ROOT. Oracle crea por defecto la CDB "FREE".

PDB (Pluggable Database)

Base de datos "enchufable" con la que trabajan los usuarios. Solo tiene sus datafiles y temporales, con su propio diccionario de datos. Por defecto se crea FREEPDB1.

PDB$SEED

Plantilla para crear nuevas PDB. Es de solo lectura (con_id = 2).

FILE_NAME_CONVERT

Indica de dónde coger los ficheros de la plantilla y a dónde copiarlos para la nueva PDB.

Estado de una PDB nueva

Queda en MOUNTED. Hay que abrirla (OPEN) para que pase a READ WRITE.

SAVE STATE

Guarda el estado de la PDB para que se abra sola al arrancar la instancia.

Clonar PDB

Crea una copia de otra PDB.

UNPLUG (desconectar)

Genera un fichero XML con la información necesaria para volver a conectar la PDB a esta CDB o a otra.

PLUG (conectar)

Vuelve a crear la PDB a partir del XML. Con NOCOPY se indica que los datafiles ya están en su sitio.

DROP ... KEEP DATAFILES

Quita la PDB conservando sus ficheros. Es el paso previo para volver a enchufarla en la misma CDB con el mismo nombre.

Requisitos para crear una PDB desde la plantilla

  • Privilegios SYSDBA.
  • Contenedor raíz abierto.
  • PDB$SEED disponible (sin modificar).
  • DB_CREATE_FILE_DEST configurado si no se usa FILE_NAME_CONVERT.

Gestión de espacio

Ubicación de los ficheros

La CDB tiene sus tablespaces y datafiles en /opt/oracle/oradata/FREE. Cada PDB tiene los suyos en /opt/oracle/oradata/FREE/NOMBRE_PDB.

Cuota (QUOTA)

Para que un usuario escriba en un tablespace necesita cuota en él.

DEFAULT TABLESPACE

Tablespace donde se crean los objetos de un usuario si no se indica otro.

Qué necesita un usuario para crear tablas

CREATE SESSION (conectarse), CREATE TABLE y cuota en el tablespace.

SMALLFILE frente a BIGFILE

SMALLFILEBIGFILE
DatafilesVarios (hasta 32 GB cada uno)Solo uno, muy grande
Tamaño máximo—El profe: hasta 8 exabytes. El PDF: hasta 128 TB
Añadir ficherosSíNo
Frase de enunciado"Con posibilidad de añadir nuevos ficheros""Un solo fichero sin posibilidad de añadir ficheros"

Por defecto Oracle crea los tablespaces como BIGFILE. Si quieres poder añadir ficheros hay que indicar SMALLFILE. La columna bigfile de dba_tablespaces indica YES (bigfile) o NO (smallfile).

Si me quedo sin espacio en un tablespace

Opción 1: redimensionar el datafile

Vale para SMALLFILE y BIGFILE. Al reducir, solo funciona si los datos no ocupan más allá del nuevo tamaño.

Opción 2: añadir un nuevo datafile

Solo si el tablespace es SMALLFILE. Si es BIGFILE y se necesita esta opción, hay que borrarlo y crearlo como SMALLFILE.

Verificar el funcionamiento

Procesos

Se comprueba que los procesos background de la instancia están en marcha. En Docker se filtran por el nombre de la BBDD (FREE).

Acceso local

Conexión como SYSDBA y consulta de v$instance. El estado debe ser OPEN.

Acceso desde red

El listener debe estar levantado y mostrar los servicios. Se comprueba con lsnrctl status. Desde otra máquina se conecta con el servicio de red.

¿Qué diferencia hay entre instancia y base de datos?
La instancia es la memoria (SGA + PGA) y los procesos. La base de datos son los ficheros en disco: datafiles, control files y redo logs.
¿Qué es la SGA y qué partes tiene?
La memoria compartida de la instancia: Shared Pool (library cache + dictionary cache), buffer de datos y buffer redo log.
¿Qué es la PGA?
Memoria privada reservada para cada proceso servidor que atiende a un cliente.
Diferencia entre procesos servidor y procesos background
Los servidor atienden las peticiones de los clientes. Los background hacen las tareas internas del gestor.
¿Para qué sirven los ficheros redo log y qué contiene un registro de redo?
Guardan todas las modificaciones (INSERT, UPDATE, DELETE) para recuperar la BBDD si hay problemas. Un registro contiene identificación de la transacción, dirección de bloque, nº de fila, nº de columna, valor anterior y valor nuevo.
¿Qué es un fichero de control y por qué tener varias copias?
Guarda la estructura de la BBDD (nombres de ficheros, checkpoints, arranque y parada, fecha y nombre). Se tienen mínimo 2 copias en discos distintos para restaurar si uno se daña.
Nombra los tablespaces que crea Oracle al instalar
SYSTEM (diccionario de datos), SYSAUX (auxiliar), USERS (datos de usuarios), TEMP (temporales) y UNDOTBS1 (deshacer).
Ordena la estructura lógica de Oracle. ¿Y la física?
Lógica: base de datos > tablespace > segmento > extensión > bloque Oracle. Física: ficheros de datos formados por bloques del sistema operativo.
¿Puede un datafile pertenecer a dos tablespaces?
No. Un tablespace tiene uno o varios datafiles, pero cada datafile es de un único tablespace.
¿Qué es un esquema y qué es el diccionario de datos?
Esquema: conjunto de objetos de un usuario (esquema = usuario). Diccionario: información sobre la propia BBDD, con vistas DBA_, ALL_, USER_ y V$.
¿Qué hacen COMMIT y ROLLBACK?
COMMIT confirma y establece la imagen nueva de los datos. ROLLBACK deshace y vuelve a la imagen antigua.
¿Qué es el listener y en qué puerto escucha?
El proceso que recibe las conexiones por red de los clientes y las pasa a la instancia. Puerto 1521.
¿Qué es una CDB y qué es una PDB?
La CDB es la base de datos contenedora (CDB$ROOT; en Docker, FREE) con control files, redo y undo. La PDB es una base de datos enchufable con sus propios datafiles, temporales y diccionario; es con la que trabajan los usuarios (por defecto FREEPDB1).
¿Qué es PDB$SEED y qué hace FILE_NAME_CONVERT?
PDB$SEED es la plantilla de solo lectura para crear nuevas PDB (con_id = 2). FILE_NAME_CONVERT indica de qué carpeta coger los ficheros de la plantilla y a cuál copiarlos.
¿En qué estado queda una PDB recién creada y para qué sirve SAVE STATE?
Queda en MOUNTED y hay que abrirla (OPEN) para pasarla a READ WRITE. SAVE STATE guarda el estado para que se abra sola al arrancar la instancia.
¿Qué genera un UNPLUG?
Un fichero XML con la información necesaria para volver a conectar la PDB a esta CDB o a otra.
Diferencia entre SMALLFILE y BIGFILE
SMALLFILE admite varios datafiles (hasta 32 GB cada uno). BIGFILE solo uno, pero muy grande (el profe: hasta 8 exabytes; el PDF: 128 TB). Por defecto Oracle crea BIGFILE.
Si me quedo sin espacio en un tablespace, ¿qué hago?
Opción 1: redimensionar su datafile. Opción 2: añadirle un nuevo datafile, solo si es SMALLFILE.
¿Cómo vuelves a enchufar una PDB desconectada en la misma CDB?
Con DROP PLUGGABLE DATABASE ... KEEP DATAFILES, después CREATE PLUGGABLE DATABASE ... USING 'fichero.xml' NOCOPY, y por último OPEN y SAVE STATE.
¿Qué necesita un usuario para crear tablas en un tablespace? ¿Y qué es DEFAULT TABLESPACE?
CREATE SESSION, CREATE TABLE y cuota en ese tablespace. DEFAULT TABLESPACE es donde se crean los objetos del usuario si no se indica otro.
¿Para qué sirven -v oradata, ORACLE_PWD y ENABLE_ARCHIVELOG en el docker run?
-v crea un volumen para que los datos persistan aunque se borre el contenedor. ORACLE_PWD es la contraseña de SYS y SYSTEM. ENABLE_ARCHIVELOG archiva las transacciones de los redo logs antes de sobrescribirlas.
